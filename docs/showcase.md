# EdgeFall：技术作品集展示指南

EdgeFall 展示一条从问题分析、模型设计、数据监督与训练，到评测、失败分析和在线演示的完整工程路径。本页提供 3–5 分钟讲解顺序，也方便读者沿着代码与实验记录继续查看。

## 一句话介绍

> 在同一次人体检测计算中复用多尺度视觉特征，再用历史运动几何检索人物和场景证据，让单目视频跌倒识别具有可追溯的时序判断与事件演示。

## 项目体现的技术能力

| 能力 | 项目中的具体实现 | 可检查的证据 |
|---|---|---|
| 从错误现象提出建模假设 | 用历史几何、局部人物与全局上下文处理单帧坐卧/跌倒混淆 | [方法设计](method.md)与最终模型源码 |
| 控制计算与状态开销 | YOLO26s 的同次前向提供检测和空间特征，历史保留稀疏特征而非重复运行视频主干 | 12.21M 参数、输入契约、时延分解与历史窗口 |
| 组织数据与监督 | 固定划分、主人物人工修订、困难负候选和困难正视频 | [数据集](datasets.md)、[训练配置与复现路径](training.md) |
| 保持实验可核查 | 完整验证域选模、验证阈值锁定、缓存和在线协议分别报告 | [评测报告](benchmarks.md)与 `reports/` 原始摘要 |
| 打通模型到应用 | Python 推理、FastAPI、Vue、逐人物遥测和事件展示 | [部署演示](deployment.md)与 [Python API](api_zh.md) |

“多模态”在这里指几何与视觉表示；输入仍为单目视频，没有音频、深度或穿戴设备。

## 3–5 分钟讲解顺序

| 时间 | 讲解内容 | 展示材料 |
|---|---|---|
| 0:00–0:40 | **问题与动机。** 坐下、弯腰和正常躺卧可能与跌倒具有相似单帧外观，因此需要动作前后关系和支撑场景 | 选择跌倒与易混淆正常活动各一个案例 |
| 0:40–1:40 | **设计选择。** 一次 YOLO 提供检测与空间特征；几何状态作为 Query 检索全局/ROI 状态；短、长分支覆盖当前到 3.2 秒历史 | [结构概览](assets/overview.svg)、[张量与采样说明](method.md) |
| 1:40–2:30 | **训练与实验。** 解释冻结特征缓存、人工主人物修订、困难样本监督，以及 epoch 与阈值仅根据验证集选择 | 训练配置、模型哈希、数据划分及指标 JSON |
| 2:30–3:40 | **运行演示。** 先展示模式和设备，再播放跌倒与正常活动，查看人物框、分数曲线、报警事件和分模块时延 | Web App 的 `live` 模式；设备不支持时显式使用 `replay` |
| 3:40–4:30 | **失败与下一步。** 展示跨域误报和长视频风险，说明优先做事件级评估、种子稳定性和设备回归 | [评测边界](benchmarks.md)、[技术路线](roadmap.md) |

`live` 会实际执行检测、跟踪和确认器；`replay` 读取保存的逐帧结果。两者都可以讲清工程接口，只有前者用于展示本次模型执行。画面中的预置标签是案例真值，分数与事件才是模型输出。

讲解“可解释”时，建议指向可追溯的输入、几何/视觉路径、分数变化及失败案例。这里的“因果”指只使用当前与历史观测，不等于完成了因果推断；注意力权重也不能单独证明某个区域是预测的原因。

公开演示使用有授权的素材，具体获取与再分发边界见[第三方材料说明](third_party.md)。

## 讲解失败分析

最值得展开的结果是 UR Fall 中 30 次跌倒全部检出，同时 40 个正常活动中有 19 个误报。这说明当前模型具备跌倒排序和召回能力，也暴露了正常动作混淆与最大值聚合的风险。只播放成功片段会掩盖需要解决的核心问题。

下一步实验可以先固定检测、特征与模型权重，比较窗口分数到事件的时间聚合，再分层检查正常坐卧、轨迹切换、遮挡和视频长度。这样可以区分问题来自视觉确认、跟踪输入还是报警策略，并给下一次模型修改提供依据。每项新实验均需单独记录配置和结果。
