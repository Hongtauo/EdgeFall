# EdgeFall 技术路线图

后续工作围绕三个问题展开：结果是否可复现、错误来自哪里、模型能否在明确的设备约束下稳定运行。路线图按可检查的实验和工程产物组织，具体顺序随数据与硬件条件调整。

## 当前基线

- 锁定模型：HN3-B-R Seed-1 Epoch 8，12.21M 参数；
- 10 FPS 因果采样，YOLO26s 共享检测与空间特征，几何与双视觉分支确认；
- 命令行视频推理、逐人物输出与 Vue/FastAPI 演示；
- 三域缓存特征测试和 UR Fall 无磁盘特征缓存在线评测；
- 原始指标、训练参数和方法文档归档。

当前没有已验收的 ONNX、TensorRT、目标 NPU 或 INT8 部署结果。公开研究集表现也尚未转换为连续长视频中的误报率与报警延迟结论。

## 方向 1：复现与工程质量

| 工作 | 验收产物 |
|---|---|
| 完成源码与依赖许可确认 | 明确源码许可证、第三方声明、权重及视频发布范围 |
| 固定模型与输入契约 | 权重哈希、环境版本、测试命令及可核查的结果摘要 |
| 补齐复现路径 | 数据获取说明、缓存生成方法、训练配置与选模协议 |
| 规范演示 | 页面持续显示 live/replay、设备与阈值；展示样本来源可追查 |

## 方向 2：错误归因与事件建模

| 工作 | 验收产物 |
|---|---|
| 分析正常坐卧、跪地和支撑动作 | 按场景、动作和置信度分层的失败案例集 |
| 评估时间最大值聚合与事件策略 | 在锁定验证协议下比较事件召回、每小时误报和报警延迟 |
| 检查多人遮挡与轨迹切换 | 人数、遮挡和人物切换分层报告 |
| 验证重复训练稳定性 | 多种子结果、区间估计及一致的选模规则 |
| 比较几何、全局与 ROI 的作用 | 相同数据协议下的分支消融与失败类别对照，不将注意力图当作因果证据 |

变更后的模型与事件策略使用新版本标识，并重新标定验证阈值。现有测试集不参与阈值调优。

## 方向 3：部署与性能回归

| 工作 | 验收产物 |
|---|---|
| 固定目标平台与接口 | 具体 GPU/NPU 型号、工具链、输入分辨率、人数和功耗约束 |
| 验证导出路径 | ONNX 或 TensorRT 转换结果及逐层/最终分数回归；跟踪和历史状态的接口定义 |
| 评估量化 | 代表性校准集、INT8 误差和完整测试指标回归 |
| 测量完整链路 | 包含解码、预处理、检测、跟踪、历史维护和报警的端到端耗时、峰值内存及稳定性 |

导出成功与性能验收分别记录；仅有模型文件或 CUDA 算法耗时，不能替代目标设备验收。

## 方向 4：连续视频评估

| 工作 | 验收产物 |
|---|---|
| 建立有授权的连续视频集 | 场景、摄像机视角、光照、人数、遮挡与视频时长记录 |
| 从视频标签过渡到事件分析 | 事件起止标注、匹配规则、报警延迟与重复报警统计 |
| 长时间运行 | 每小时误报、事件召回、历史状态内存和服务稳定性报告 |
| 检查应用边界 | 并发、断流恢复、任务隔离、资源释放与版本回归 |

当前演示提供本地事件展示和确认操作。连续输入、并发与断流恢复需要在新的运行协议下单独检查。

## 每次迭代留下什么

每项实验保留设计假设、配置、数据版本、验证选模规则、测试结果和失败案例；每项部署改动保留功能回归与性能测量。优先完成能够区分错误来源的实验，再决定是否增加网络复杂度。项目展示以这些可核查的技术产物呈现设计判断和工程能力。
